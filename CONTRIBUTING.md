# Contributing to chertmem

Thanks for looking. This page is the short version of how work lands
here; the rules themselves live in the specs and in the gate that
enforces them.

## Getting set up

Enter the dev shell with `nix develop`, or `direnv allow` once. Every
tool the gate runs comes from it, pinned by `flake.lock`, and on the
systems pklith supports the shell points git at the tracked hooks in
`.githooks/`. Node is in the shell for one reason only: the grammar
tests run cavemem 0.2.1's JavaScript as an oracle. It is never part of
the `chert` binary.

```sh
nix develop --command cargo nextest run --workspace
```

## The gate

Every commit runs hk's pre-commit and commit-msg hooks; every push runs
the full gate, tests and line coverage included. Run it by hand with
`hk check --all`. The hooks refuse when hk is missing, because a gate
that did not run has not passed. Never use `--no-verify`: when the gate
refuses, its message says what to fix.

The gate's steps are declared in [`.pklith`](.pklith), one row each,
and every tracked file type has a row there. A new file type needs a
row before it can be committed.

## Commits

- One change per commit.
- Subject `type(scope): claim`, at most 72 characters, with type one of
  `feat`, `fix`, `docs`, `test`, `chore`, `refactor`, `perf`, `build`
  or `ci`. The body says why.
- The last paragraph carries the trailers, `Paradigm-Stage:` among them.
- Tests first: a commit that adds Rust code needs a `test:` commit
  before it in the push, the failing (RED) test that the code then
  makes pass.
- A new gate step comes with proof, in its commit body, that it rejects
  a planted violation.
- No local absolute paths and no names of private repositories in
  anything committed.

## Design

The design is a federated spec: [`SPEC.md`](SPEC.md) at the root and
one `SPEC.md` per node under `src/`, `benches/`, `dev/` and `docs/`.
Change the spec in the same series as the code it describes. The
navigation tables are generated by sherd; never edit them by hand. The
format is in [`FORMAT.md`](FORMAT.md) and
[`FORMAT-EXTENSIONS.md`](FORMAT-EXTENSIONS.md).

chert's priorities, when they conflict: correctness first, then speed.
A faster answer that is less correct is not accepted, and the cache
must give the same answer as the disk.

## Reporting problems

Bugs and ideas go in GitHub issues. Security problems go through
[`SECURITY.md`](SECURITY.md), not a public issue.
